## Required engineering method
Follow the root `ENGINEERING_EXECUTION_OS.md`: OUTCOME → INSPECT → SPECIFY → PLAN → EXECUTE → VERIFY → REVIEW → CLOSE.
- Inspect real files, issues, branches, PRs, workflow runs, logs, and deployments before conclusions.
- Establish baseline and preserve unrelated work.
- Convert requirements into numbered acceptance criteria and evidence mappings.
- Prefer the smallest complete root-cause fix.
- Verify resulting diffs and actual behavior; build success is not runtime proof.
- Use [V] verified, [C] reported, [I] inference, [A] assumption, [U] unknown, [B] blocker. Do not upgrade reported claims into verified facts.
- Every execution report follows the TOOL DECLARATION and COMPLIANCE HEADER defined in the root OS.
