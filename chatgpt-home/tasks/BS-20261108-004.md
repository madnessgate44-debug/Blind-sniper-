### Safety behavior
- A started-without-completed action is not automatically retried; it requires reconciliation because the browser side effect may already have happened.
- If the lease expires during a bounded browser command, the action receipt is still persisted and explicitly records `lease_valid_after_action=false`.
- This bridge does not create or renew leases, grant approvals, or make an ephemeral runner persistent.
- The lease is checked immediately before dispatch with a timeout safety margin. This is not a distributed lock held across the browser command; the post-action lease status is recorded for audit.

## Atomic reservation hardening and re-verification

Final review identified that a read-then-append sequence could allow two concurrent workers to observe an unreserved step before either append completed. This was a genuine race, so the earlier sequential duplicate guard was not sufficient.

**Corrective implementation:**
- `TaskLedger.reserve_browser_action_if_lease` now performs authoritative EXECUTING-state, implementer identity, active-lease budget and step-reservation checks under one file lock.
- `GitHubContentsLedger.reserve_browser_action_if_lease` applies the same validation against the private remote ledger and commits through its SHA compare-and-swap loop.
- The dispatcher uses this atomic reservation before browser invocation, then rechecks lease ownership/budget immediately before constructing the adapter.
- A concurrent reservation test requires exactly one successful reservation and one rejection.
- A started-only interrupted step remains blocked and must be reconciled.

**Failed verification attempt:** browser run `42494162008` and runtime run `42494162021` failed because the first remote-ledger method insertion landed inside `TaskLedger`, shadowing its local method and referencing a nonexistent `max_retries`. Raw failure: `AttributeError: 'TaskLedger' object has no attribute 'max_retries'`; browser-dispatch suite reported 8 errors. The method has since been relocated to `GitHubContentsLedger` (verified by source inspection: local method under `TaskLedger`, remote method under `GitHubContentsLedger`).

**Current verification status:** atomic hardening code and added tests are committed, but no successful CI run has yet been observed against the corrected commit. R9–R11 are therefore **RE-VERIFICATION PENDING** for the atomic implementation. Do not claim the concurrency race is verified closed until the new browser and runtime suites pass.
