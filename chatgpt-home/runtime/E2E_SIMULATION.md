# Blind Sniper end-to-end simulation

**Purpose:** Exercise the real runtime CLI and local task ledger through a deterministic CI simulation.

## Scenario

1. Create a synthetic task and route it through native workflow/profile/agent/skill registries.
2. Persist REQUESTED, INSPECTING, SPECIFIED and PLANNED.
3. Claim the task through the runtime CLI; prove a competing owner is denied.
4. Enter EXECUTING with the lease owner. The runtime commits the transition under the ledger's atomic lease lock and records that owner as implementer.
5. Generate and SHA-256 verify a deterministic local artifact.
6. Persist VERIFYING, replace the convenience checkpoint with stale state, and recover VERIFYING from the ledger.
7. Resume through REVIEWING and CLOSED.
8. Release the execution lease through the CLI and verify lease-status is empty.
9. Separately exercise lease expiry/reclaim and owner-only release in an isolated local ledger.
10. Validate ordered state/lease events and upload the task envelope, commands, evidence, states, ledgers and artifact.

## What a PASS proves

- The actual runtime CLI can plan, claim, reject a competing claim, require a lease for EXECUTING, release the lease and inspect lease status.
- The EXECUTING state append validates lease ownership atomically under the local ledger lock and binds implementer_id to the lease owner.
- A stale checkpoint can be reconstructed from the append-only hash-chained ledger after an injected interruption.
- The resumed task can verify its artifact and reach CLOSED under the current metadata gates.
- Local lease expiry/reclaim and owner release behave as specified.
- The receipt is correlated to the exact GitHub commit and workflow run.

The runtime unit suite also tests GitHub Contents CAS remote lease claim, release, status and atomic execution-transition ownership using a fake transport, plus refusal to access public repositories.

## What a PASS does not prove

- No external agent/model is spawned; the execution artifact is generated by this deterministic harness.
- No OpenHands, Forge, browser, provider key, external API or paid service is invoked by the E2E simulation.
- GitHub CAS adapter tests use a fake transport; no live authenticated remote ledger write is performed.
- The reviewer is a deterministic test harness, not a human or independent model reviewer.
- The E2E lease exercised here is local-workspace only. The remote CAS lease adapter is mock-tested, not live-verified against a private repository.
- Uploading a 14-day CI artifact is evidence retention, not a transactional shared task store or unattended ChatGPT execution.

## Run

The Blind Sniper Runtime Registry workflow runs the simulation on matching pushes and pull requests. The receipt and raw evidence are uploaded as a GitHub Actions artifact named blind-sniper-e2e-<run_id>.

The simulation requires GitHub Actions GITHUB_SHA and GITHUB_RUN_ID environment variables and intentionally fails closed elsewhere.

## Scheduled-jobs simulation

`scripts/simulate_blind_sniper_jobs_e2e.py` is a second deterministic simulation
that models the continuous-autonomy pipeline named in `workflows.json`
(`receive -> deduplicate -> dispatch -> retry with loop breaker -> persist state
-> deliver`) across a fixed set of scheduled ticks, using the real local task
ledger for the dispatch lease and the append-only audit chain.

Scenario:

1. Two jobs run on their own cadences: a daily job (`0 9 * * *`) and a two-hour
   job (`0 */2 * * *`). A job only fires when its next-run time is reached, so the
   daily job fires once across the window and does not fire early.
2. Events arrive on the two-hour job; a redelivered event with a seen key is
   deduplicated instead of dispatched again.
3. Dispatch claims one execution lease and proves a competing owner is denied.
4. A task that fails then succeeds on retry; a task that keeps failing trips the
   loop breaker after the configured consecutive-failure threshold.
5. A later tick is skipped because the breaker is tripped.
6. Each completed task produces a SHA-256 delivery receipt; the ledger hash chain
   and event sequence are re-read and verified.

What a PASS proves: the pipeline's receive/deduplicate/dispatch/retry/loop-breaker
/skip/deliver controls hold, dispatch honours the exclusive ledger lease, and the
job audit ledger is intact and contiguous.

What a PASS does not prove:

- No real scheduler or background trigger exists. The receipt records
  `real_scheduler_present: false` and `scheduler_kind:
  deterministic_test_harness_not_a_real_scheduler`. Ticks are simulated, not
  delivered by a clock.
- No agent, model, provider, browser or network call is made
  (`actual_agent_spawned: false`, `external_network_calls: 0`).
- It does not verify the OpenHands automation receiver or any external task
  delivery route; the `automation` capability remains
  `available_but_receiver_unverified`.

Run:

    GITHUB_SHA=$(git rev-parse HEAD) GITHUB_RUN_ID=123456789 \
      python scripts/simulate_blind_sniper_jobs_e2e.py --output-dir artifacts/blind-sniper-jobs-e2e

Like the runtime simulation it requires GitHub Actions `GITHUB_SHA` and
`GITHUB_RUN_ID` and fails closed elsewhere. The runtime workflow runs it on
matching pushes and pull requests and uploads the receipt as part of the
`blind-sniper-e2e-<run_id>` artifact.
